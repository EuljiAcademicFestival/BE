## 21. 종료된 연결의 늦은 메시지를 별도 집계 — 구현·회귀 검증

기록일: <date start="2026-11-16" />

20번에서 확인한 퇴장과 마지막 MOVE 경합을 수정했다. 이미 종료된 연결의 늦은 메시지를 적용하지 않고 ignored로 별도 집계한다. 마지막 이동 완료까지 퇴장을 지연시키거나 새 대기열·공간 잠금을 추가하지 않는다.

### 적용 범위

- 입력 판정 시 연결이 이미 제거됐거나 닫혀 있으면 재종료 없이 무시한다.
- 입력 판정 후 인증 상태를 확인하는 사이 연결이 종료된 경우도 구분한다.
- 공간 처리 시 캐릭터가 없고 연결도 종료됐으면 CONNECTION_CLOSED로 구분해 ignored로 집계한다. MOVE와 PING에 적용된다.
- 캐릭터는 없지만 연결은 열려 있으면 기존 AUTH_REQUIRED 오류를 유지한다.
- 연결 종료와 무관한 잘못된 JWT·좌표·메시지 형식·실제 빈도 제한은 기존 거부 처리와 종료 규칙을 유지한다.
- 종료된 캐릭터를 복원하거나 마지막 좌표를 다시 전파하지 않는다. 위치 정밀도·전송 주기·전체 맵 위치 제공은 그대로다.

여기서 ignored는 “이미 닫힌 연결의 메시지”를 뜻하며, 모든 연결 종료 원인이 정상이라는 의미는 아니다. 네트워크·송신 오류 자체를 이 지표로 정상화하지 않는다.

### 지표

기존 accepted/rejected 및 거부 사유 지표는 유지하고 아래 카운터를 추가했다.

```promql
festival_websocket_messages_total{result="ignored",type="unknown"}
festival_websocket_ignored_total{reason="CONNECTION_CLOSED"}
```

본문을 해석하기 전에 무시하는 경우도 있어 type은 고정값 unknown을 사용한다. ID·JWT·임의 메시지 종류를 라벨에 넣지 않는다. 종료 후 무시된 메시지가 오류에서 빠져도 횟수는 남으므로 숨기거나 성공 처리한 것으로 집계하지 않는다.

### 검증

관련 테스트 30개 통과, 실패·오류·건너뜀 0개. bootJar 빌드 성공.

- 실제 공간 잠금을 사용해 MOVE 인증 확인 후 연결·캐릭터 제거가 먼저 수행되는 순서를 재현했다. ignored 1건·rejected 0건이고 캐릭터 수는 0으로 유지된다.
- 캐릭터만 제거됐지만 연결은 열린 상태라면 AUTH_REQUIRED와 기존 종료 동작을 유지한다.
- 연결 정리 후 마지막 MOVE, 이미 닫혔지만 채널이 남은 소켓, 입력 판정과 인증 조회 사이 종료를 검증했다.
- 실제 빈도 초과·잘못된 좌표·인증 전 이동·잘못된 JWT·ID 위조 등 기존 오류 검증이 통과했다.
- 기존 위치 3자리 반올림·원본 보존·입퇴장·느린 수신자·좋아요 배치·실제 임의 포트 소켓 회귀 검증이 통과했다.

코드: FestivalPresenceService.java, FestivalWebSocketHandler.java, PresenceMetrics.java.
핵심 회귀 테스트: PresenceRejectionReasonTest.java.

### 실측 상태

사용자 8080 서버는 이번 코드로 재시작하지 않았다. 수정 후 200명 부하는 아직 실행하지 않았다. 재시작 후 동일 조건에서 AUTH_REQUIRED·RATE_LIMIT 등 거부 증가와 ignored 증가를 분리해 확인해야 한다. 기존 실측 32건을 0건으로 바꾸지 않고 개선 후 실행을 뒤에 추가한다.

프론트엔드 요청·응답 형식은 변경되지 않아 WebSocket 명세에는 내부 계측·검증 기록을 추가하지 않는다.
