# DB 연결 대기 증가 확인

2026-11-15, 쿼리 최적화 전후 부하테스트의 기존 Prometheus 이력과 앱 로그를 조회했다.
추가 부하나 데이터 변경, 서버 설정 변경은 실행하지 않았다.

## 확인된 사실

기존 15초 간격 별도 수집에서는 대기 인원이 최대 64 → 136으로 관측됐다.
그러나 이 수치는 대기한 시간이 아니라 샘플 순간의 대기 스레드 수다.
실제 연결 획득·점유 시간과 GC는 Prometheus의 약 5초 간격 이력으로 추가 확인했다.

| 지표 | 쿼리 최적화 전 | 쿼리 최적화 후 |
| --- | ---: | ---: |
| 본 부하 평균 연결 획득 시간 | 1.821ms | 1.609ms |
| 본 부하 평균 연결 점유 시간 | 0.939ms | 0.921ms |
| 관측된 최대 연결 획득 시간 | 99ms | 125ms |
| 200명 유지 구간 평균 연결 획득 시간 | 1.840ms | 1.586ms |
| 200명 유지 구간 평균 연결 점유 시간 | 0.906ms | 0.884ms |
| 200명 유지 구간에서 관측한 점유 시간 max | 20ms | 21ms |
| 연결 획득 타임아웃 증가 | 0 | 0 |
| 본 부하 GC 정지 시간 합계 | 867ms | 705ms |
| 본 부하에서 관측한 GC pause max | 11ms | 14ms |

평균은 해당 구간 첫·마지막 수집점의 timer sum 차이를 count 차이로 나눴다.
전 측정은 02:21:36~02:28:38, 후 측정은 03:20:31~03:27:32 KST 범위의 실제 수집점을 사용했다.
200명 유지 구간은 각각 02:25:06~02:28:06과 03:24:01~03:27:01 범위다.
시작·끝은 수집 시점에 맞춰지므로 k6의 모든 요청과 정확히 같은 경계는 아니다.
준비 단계 로그인은 약 0.4초까지 연결을 점유하므로 전체 실행의 점유 max와 구분했다.
timer의 `_max`는 일정 시간 유지되는 최댓값이며 정확한 이벤트 발생 시각을 뜻하지 않는다.

## 136개가 관측된 구간

- 별도 수집 시각: 03:23:19.935 KST. 시나리오상 약 100명 유지 구간이다.
- 연결 10개 사용, 연결 대기 136개, Tomcat 처리 중 스레드 149개였다.
- 여러 API의 전체 요청 시간이 동시에 길어졌고 해당 초 로그에서 최대 86ms였다.
- 같은 초의 서비스 메서드 로그는 최대 2ms였지만, 이 로그는 트랜잭션 경계와
  로깅 호출 자체를 포함한 전체 요청 시간과 같지 않다. AOP 순서에 따라 해석도 달라진다.
- Prometheus는 주변 03:23:16.355와 03:23:21.355에서 모두 대기 인원 0을 기록했다.
  수집 시점 차이로 순간 급증을 놓칠 수 있음을 확인했다. 정확한 지속 시간은 알 수 없다.
- 같은 주변 시점의 GC pause max는 4ms였다. 긴 GC 정지를 주원인으로 지목할 근거는 없다.

Prometheus의 자체 샘플에서 대기 인원 최댓값은 전 42, 후 72였다.
별도 수집의 64·136과 다르므로 서로 다른 수집 간격·시점의 최댓값을 혼동하지 않는다.

## 판단과 남은 불확실성

**평균적인 연결 대기와 점유는 감소했지만 순간적인 연결 풀 경합은 남아 있다.**
쿼리 최적화 후 지속적으로 DB 연결을 더 오래 점유한다거나 GC가 대폭 악화됐다는 증거는 없다.
다수 요청이 제한된 10개 연결을 경쟁하는 상황과 일치하지만, 두 실행의 순간 최대가
달라진 직접 원인(요청 동기화, 스케줄링, DB 처리·잠금, JVM/로그 처리 등)은 기존 이력만으로 확정할 수 없다.

코드상 인증 조회와 비즈니스 처리는 각각 별도 트랜잭션이다.
메트릭도 API 요청당 약 두 번의 연결 획득과 일치한다. 요청당 5개 조회를 병렬 실행하므로
동시 사용자 100명은 DB 동시 요청 100개로 제한된다는 뜻이 아니다.
인증 및 트랜잭션 경계의 연결 비용도 다음 분석 대상이다.

정확한 사건 단위 원인을 확인하려면 다음 실행에 요청별 연결 획득/반납 타이밍,
JFR 또는 GC·스레드/DB 잠금 이벤트를 함께 수집해야 한다.
연결 풀 크기나 캐시는 이번 확인 작업에서 변경하지 않았다.
