# 인증 조회 트랜잭션 비용 축소

## 변경

`MemberAuthenticationService`의 클래스 수준 `@Transactional(readOnly = true)`를 제거했다.
보안 필터가 호출하는 토큰 검증은 `JdbcTemplate`의 단일 SELECT이므로 별도의 서비스 트랜잭션을 시작하지 않는다.
토큰 해시·만료 시각·회원 존재 여부를 확인하는 SQL과 API 응답은 유지했다.
가입·로그인 및 비즈니스 서비스의 트랜잭션은 유지했다. 캐시와 연결 풀 설정은 변경하지 않았다.

인증 쿼리도 여전히 DB 연결을 빌린다. 따라서 요청당 연결 획득이 2회에서 1회로 줄어드는 변경은 아니다.
줄이려는 대상은 인증 단일 조회를 감싸던 트랜잭션 설정·시작·종료 비용과 연결 점유 시간이다.
이미 트랜잭션이 있는 다른 호출자가 사용하면 기존 트랜잭션의 연결을 사용할 수 있다.
이번 변경의 검증 대상 경로는 트랜잭션 밖에서 호출되는 보안 필터다.

## 검증

- 변경 전, 보안 필터의 인증 조회에 활성 트랜잭션이 없어야 한다는 회귀 테스트가 실패해 기존 동작을 재현했다.
- 변경 후 같은 테스트와 전체 테스트 **31개 통과**. 실패·오류·건너뜀 0개.
- 실제 MySQL의 분리된 `eulji_festival_test` DB에서 검증했고 bootJar 빌드가 성공했다.
- 유효 토큰의 정상 접근과, 토큰 삭제·만료·회원 삭제 후 다음 요청의 401을 검증했다.
- 빈 토큰, 잘못된 형식, 존재하지 않는 토큰, 잘못된 인증 방식의 거부를 검증했다.
- 기존 가입·프로필 롤백, 좋아요 동시성, 전역 공동 순위·커서 회귀 테스트도 통과했다.

## 성능 검증 상태

코드 변경과 기능 검증은 완료했다. 8080 서버를 재시작해 반영한 뒤 같은 200 VU 혼합 부하로 비교해야 한다.
현재 단계에서는 연결 대기가 감소했거나 해결됐다고 주장하지 않는다.
비교 대상은 요청 오류·좋아요 정합성, 연결 획득·점유 시간, 연결 대기와 API 지연이다.
계측을 추가한 실행과 기본 실행을 구분하고 평균 및 순간 최대를 함께 비교한다.
